## Вердикт

> **ДОКАЗАНО СТРОГО (интервальная арифметика Arb, направленное округление):**
> `wind(x_{2^m}, Γ) = 0` на контуре **всех 23 обязательных** кольцевых дисков
> **и** на **обоих** дополнительных дисках радиуса 1/6 (D_MINUS, D_PLUS) —
> т.е. **25/25**. Отсюда по принципу аргумента `x_{2^m}` не имеет нулей
> **внутри** ни одного из этих дисков, значит `arg(x_{2^m}) = Im log x_{2^m}`
> — однозначная гармоническая функция на каждом диске.

Худший запас (минимум `|x_{2^m}|` на контуре, строгая нижняя оценка по всем
25 дискам): **1.1166×10⁻³** (диск `D_MINUS`). Среди 23 обязательных дисков
худший запас: **2.3636×10⁻³** (диск `Z72`, m=8) — согласуется с ЧИСЛЕННОЙ
(NOT RIGOROUS) оценкой из `article_v1/v2_work/poles/REPORT_POLES.md`
(2.367×10⁻³ для Z72, 4.35×10⁻³…7.71×10⁻³ для остальных 22): строгая нижняя
граница чуть ниже точечной оценки, как и ожидается.

**Тампер-батарея:** 8 порч (минимум по брифу — 6). Итог — см. `TAMPER_LOG.md`.

## 2. Метод (не переоткрыт, а заимствован из уже проверенного кода)

Дуговая машина `w36/audit_codex/cert_slice_param_audit.py` (строки 411-414:
`inv=af_recip(x128); H=af_mul(x,inv)`) и, что важнее, "light single-symbol AF"
из `census_A_certificate.py` (`H7_light`/`compute_winding`, строки ~304-390,
тот же приём в census_B/point14/point3B_fix1) — это уже ПРОВЕРЕННЫЙ архивом
способ считать обмотку через: (а) дуговое affine-покрытие контура одним
комплексным диск-символом, (б) проверку "диск не содержит 0" на каждой дуге,
(в) сумму `arg()` по КОНЦАМ дуг (точечные шары, без ширины дуги).

**Ключевой геометрический факт** (использован архивом неявно, здесь — явно
обоснован и вынесен в сертификат): если affine-диск некоторой величины на
дуге имеет `|center|_lower > radius_upper` (т.е. диск не содержит 0), то
угловой раствор образа ЭТОЙ ДУГИ строго меньше `pi` (элементарно: диск радиуса
R с центром c, R<|c|, вписан в сектор полуугла `asin(R/|c|) < pi/2`). Значит
сумма `arg()` по концам дуг (принципиальная ветвь `(-pi,pi]`) — это ТОЧНОЕ
непрерывное приращение аргумента без обёртывания (wraparound), при условии,
что КАЖДАЯ дуга прошла проверку "диск не содержит 0". Это то же самое условие,
что census-сертификаты УЖЕ проверяют для `H_m` — здесь оно проверяется для
**самого знаменателя** `x_{2^m}` (числитель отбрасывается: цикл орбиты
останавливается на `n=2^m`, а не идёт до `2^(m+1)`, что дешевле, чем считать
полное отношение).

**Смыкание покрытия контура** (обязательное условие из брифа, отдельное поле
в сертификате):
1. **Угловое разбиение** — точное (`Fraction`), дуги `t=k/N,(k+1)/N`,
   `k=0..N-1`; сумма ширин `=1` ровно, без зазоров по построению (проверяется
   явно, поле `tiling_ok`).
2. **Покрытие дуги диском** — расстояние от середины дуги (на окружности) до
   любой точки дуги максимально на концах и равно
   `chord = 2·rho·sin(pi·dt/2)` (элементарная геометрия окружности; это ТОЧНОЕ
   покрытие всей дуги, не приближение). `chord` вычислен через `flint.arb`
   (корректно округлённый шар, не `math.sin`/`Decimal`, в отличие от
   черновой проверки `h1_proof/hole1_closure_check.py`, которая явно
   маркирует себя "NOT a certificate: double arithmetic + Decimal sin").
   Взят `rho_arc = chord_upper·(1+10⁻⁶)` — запас x10⁶ раз больше, чем
   зазор чистого округления вверх; поле `arc_disk_coverage_worst_margin`
   — фактический (строгий, положительный) запас на каждом диске.

## 4. Независимая верификация (`winding_verify.py`)

Другой кодовый путь (НЕ импортирует `winding_certificate.py`):
- ручная комплексная арифметика на парах `(re,im)` вместо оператора `*`/`/`
  типа `flint.acb`;
- прямое накопление степеней `z^0..z^99` (forward) вместо Horner (backward) —
  другой алгоритм вычисления `g(w)`,`h(w)`;
- формула хорды через `cos`-тождество `rho·sqrt(2-2cos(pi·dt))` вместо
  `2·rho·sin(pi·dt/2)` (алгебраически идентично, разные функции `flint.arb`);
- `u_mid` строится через `cos(theta)/sin(theta)` напрямую, а не через
  комплексную экспоненту;
- деление `AU0/delta^m` — рукописная формула комплексного деления;
- геометрия (центр, `rho`, `m`) перечитывается из СЫРЫХ файлов census_A/B,
  z72, fix1 и сверяется с тем, что заявляет сертификат (не наоборот).

Все 8 sha256-пинов, геометрия всех 25 дисков, все производные поля (tiling,
покрытие, домен, знаменатель, обмотка, `pass`) и верхнеуровневые агрегаты
(`n_pass_required`, `all_pass`, `n_checks`, худший `min|x|`) пересчитаны
заново и сверены другим кодовым путём. Итог — см. §4a (заполняется по
результату прогона `winding_verify.py`, лог — `_run_verify.log` в этой папке).

## 6. Что НЕ входит в эту задачу (честно)

- Вопрос полюсов для **H1** закрыт СТРУКТУРНО (автономная орбита, `x_0=0` ⟹
  нуль знаменателя автоматически даёт нуль числителя) — эта задача его НЕ
  переоткрывает, брифом это прямо оговорено (§3).
- Голоморфность `x_{2^m}` **внутри** диска (не только на контуре) не
  проверяется здесь заново — она следует из голоморфности композиции `g,h`
  (полиномиальные ряды) на всём диске композиции `|w|<1`, что уже
  устанавливается доменной проверкой (`domain_ok`/`Rmax<1`) на каждой дуге,
  покрывающей контур; это тот же стандартный аргумент, что и во всех
  сертификатах архива.
- Простота нуля предельной `H` (кратность) — вне рамки этой задачи (не нуль
  `x_{2^m}`, а вопрос о пределе).
- Голоморфность `arg(x_{2^m})` как гармонической функции **на всём диске**
  (не только на контуре) — прямое следствие теоремы о принципе аргумента
  (голоморфная функция без нулей на односвязной области имеет голоморфную
  ветвь `log`), а не отдельная проверка; несёт её именно факт `wind=0`,
  доказанный здесь строго.
