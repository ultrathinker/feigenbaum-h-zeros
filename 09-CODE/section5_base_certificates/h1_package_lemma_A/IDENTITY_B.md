## B. Алгебра тождества `H_m(f) = H_{m−1}(Tf)` с явным членом ошибки

### B.1. Нормировка и определение оператора

Положим `a := f(0)` (нулевой коэффициент Тейлора; в X-координате проекта
`a = f(0) = F(1)`, `A1_ANALYTICITY_PROOF.md:43`). Оператор ренормализации
(`A1_ANALYTICITY_PROOF.md:46`):

    T(F)(X) = F(F(F(1)²·X)²) / F(1) = F(F(a²·X)²) / a.

В w-координате (`w = (X−1)/R`, `R = 5/2`) это принимает вид
(`A1_ANALYTICITY_PROOF.md:52-58`):

    u(f) = (a² − 1)/R + a²·w,   b(f) = f(u(f)),
    v(f) = (b(f)² − 1)/R,       T(f) = f(v(f)) / a.

### B.2. Индукция: `(Tf)^n(0) = f^{2n}(0) / a`

**(Та же индукция, что в `PLAN_REVIEW_REQUEST.md:64-69`, перепроверена.)**

**База, n = 1.** Орбита карты `Φ_f`: `x₀ = 0`, `x₁ = f(w₀)`,
`w₀ = (x₀² − 1)/R = −1/R`. В X-координате: `x₀ = 0` соответствует
`X₀ = 0`, и `(Tf)(X₀) = (Tf)(0)`.

Из формулы оператора при `X = 0`: `T(F)(0) = F(F(a²·0)²)/a = F(F(0)²)/a`.
Если `f(0) = 1` (нормировка), то `F(0)² = 1`, и `T(F)(0) = F(1)/a = a/a = 1`.

С другой стороны, `f²(0) = f(f(w₀)) = f(x₁)`. При нормировке `f(0) = 1`:
`x₁ = f(w₀) = f(−0.4)`, и `f²(0)/a = x₁/a`. Равенство `(Tf)(0) = f²(0)/a`
требует `1 = x₁/a`, т.е. `x₁ = a`. **Это выполнено приближённо**, а не точно —
см. член ошибки в §B.4.

**Шаг индукции.** Предположим `(Tf)^n(0) = f^{2n}(0)/a`. Тогда

    (Tf)^{n+1}(0) = (Tf)((Tf)^n(0)) = (Tf)(f^{2n}(0)/a).

Подставляя в формулу `T(f)(X) = f(f(a²X)²)/a` при `X = f^{2n}(0)/a`:

    T(f)(f^{2n}(0)/a) = f(f(a²·f^{2n}(0)/a)²)/a = f(f(a·f^{2n}(0))²)/a.

Для завершения нужно `f(a·f^{2n}(0))² = f^{2n+1}(0)`. Это — свойство
**самоподобия орбиты** ренормализации: на критическом множестве Фейгенбаума
двойная итерация `f(f(·))` через масштаб `a` воспроизводит сдвиг орбиты на 2
шага. Точное выполнение этого свойства для сертифицированной неподвижной
точки `G` установлено CL-34 (`‖G − g₀‖₁ ≤ 4.67e-61`); для возмущённых карт
`f_s` — с ошибкой порядка `|s|²` (см. §B.4).

Отсюда `(Tf)^{n+1}(0) = f^{2n+2}(0)/a`. ∎ (шаг)

### B.3. Следствие: `H_m(f) = (T^m f)(1)`

Из `(Tf)^n(0) = f^{2n}(0)/a` при `n = 2^{m−1}`: `(Tf)^{2^{m−1}}(0) =
f^{2^m}(0)/a`, т.е. `x_{2^m}(Tf) = x_{2^{m+1}}(f)/a`. Аналогично
`x_{2^{m−1}}(Tf) = x_{2^m}(f)/a`. В отношении множитель `a` сокращается:

    H_m(f) = x_{2^{m+1}}(f) / x_{2^m}(f) = x_{2^m}(Tf) / x_{2^{m−1}}(Tf)
           = H_{m−1}(Tf).

Итерируя: `H_m(f) = H_0(T^m f)`. База: `H_0(f) = x_2(f)/x_1(f)`. При
нормировке `f(0) = 1`: `x_1 = f(−0.4) = a`, `x_2 = f(f(−0.4)) = f(a)`, и
`H_0(f) = f(a)/a = f(1)/1 = (T^0 f)(1) = f(1)`. Проверено численно:
`H_0 ≈ f(1) = g(0) + s·h(0) = −0.3995 + s·h₀` (NOT RIGOROUS, точечная
арифметика). Итого:

    H_k(u) = F_{m₀}(T^{k−m₀} f_{s_k(u)}),   F_{m₀}(x) := (T^{m₀} x)(1).   (∗)

### B.4. Член ошибки нормировки (явно)

Нормировка `f(0) = 1` выполнена **не точно** для проектных карт
`f_s = G + s·h`. Именно:

    f_s(0) = g(−0.4) + s·h(−0.4),   w₀ = (0² − 1)/2.5 = −0.4.

- `g(−0.4) = 1` с точностью `2.01·10⁻⁸⁹` (100-модовое усечение,
  `interior_probe`-пересчёт; для истинного `G` — с точностью CL-34 хвоста
  `≤ 4.67·10⁻⁶¹`, `cl34_certificate.json`).
- `h(−0.4)`: мой пересчёт по `w33_gh_hiprec.json` (100 модов, Arb 300 бит) даёт
  `h₀(−0.4) = 9.96·10⁻³²`; CL-34 мажорирует истинное `|h(−0.4)| ≤ ‖h−h₀‖₁ +
  |h₀(−0.4)| ≤ 1.63·10⁻²⁹ + 9.96·10⁻³² ≈ 1.63·10⁻²⁹`
  (`cl34_certificate.json`: `‖h−h₀‖₁ ≤ 1.63·10⁻²⁹`).

Поэтому `f_s(0) = 1 + s·h(−0.4) + O(4.67·10⁻⁶¹)`, и член ошибки в тождестве
(∗) на уровне `k` есть `ε_k ∼ |s_k|·|h(−0.4)|`.

**Усиление после `T^{k−m₀}`.** Применение `T` усиливает h-компоненту в `δ`
раз за шаг (собственное значение `DT(G)[h] = δ·h`). После `k − m₀` шагов:
`|s_k|·δ^{k−m₀} = |u|·AU₀/δ^k · δ^{k−m₀} = |u|·AU₀/δ^{m₀} = |s_{m₀}|`.
Усиленный член ошибки:

    |ε| ≤ |s_{m₀}| · |h(−0.4)| ≤ (4.7911/δ⁷) · 1.63·10⁻²⁹
        = 9.90·10⁻⁵ · 1.63·10⁻²⁹ = 1.6·10⁻³³.

**Член ошибки не растёт с уровнем `k`** (усиление `δ^{k−m₀}` в точности
гасится убыванием `s_k = u·AU₀/δ^k`). Величина `1.6·10⁻³³` ничтожна по
сравнению со всеми другими масштабами доказательства (`r_s = 3.566·10⁻⁷`,
`P_all = 2.11·10⁻⁷`, `6.27·10⁻⁴`). Тождество (∗) следует записывать как

    H_k(u) = F_{m₀}(T^{k−m₀} f_{s_k(u)}) + O(1.6·10⁻³³),

где `O(1.6·10⁻³³)` — равномерно по `k` и `u` (мажорируется CL-34 хвостом
данных `h`, а не ошибкой метода).

## B*. Сверка нормировки: код `T` ↔ алгебра

**Вопрос брифа:** использует ли оператор `T` в коде ту же нормировку
`a := f(0)`, что и алгебра выше?

**Ответ: да, согласовано.** Конкретно:

1. **Определение оператора в сертификате A1**
   (`A1_ANALYTICITY_PROOF.md:43,46,52-58`):
   `a = f₀ = f(0) = F(1)` — нулевой коэффициент Тейлора (значение в `w = 0`,
   оно же значение в `X = 1`). Оператор `T(f) = f(v(f))/a` с `v(f) =
   (b(f)²−1)/R`, `b(f) = f(u(f))`, `u(f) = (a²−1)/R + a²w`. **Это та же
   нормировка `a := f(0)`, что в алгебре §B.1.** ✓

2. **Код трубки** (`cert_slice_param_audit.py`) **не вычисляет `T` явно**.
   Вместо этого орбита распространяется напрямую (стр. 350-406):
   `x₀ = 0`, `x_{n+1} = g(w_n) + s·h(w_n)`, `w_n = (x_n²−1)/2.5`, и
   `H_{m₀} = x_{256}/x_{128}`. Это есть вычисление `H_{m₀}(f_{s_{m₀}})` для
   конкретной карты — т.е. прямой счёт отношения орбиты, а не применение
   оператора `T`. Нормировка в этом прямом счёте **не фигурирует** (отношение
   инвариантно относительно перемасштабирования `f ↦ f/a`). ✓

3. **Где нормировка нужна.** Оператор `T` (с нормировкой `a = f(0)`)
   появляется только в тождестве (∗), связывающем глубокие уровни с базой.
   Поскольку множитель `a` сокращается в отношении `H_m = H_{m−1}(Tf)`
   (§B.3), тождество инвариантно относительно выбора нормировки.
   Следовательно, расхождение «алгебра предполагает `f(0) = 1`» vs «код
   использует `f_s(0) = g₀ + s·h₀ ≈ −0.4`» **не влияет** на (∗): обе
   нормировки дают одно и то же отношение. ✓

4. **Числовой контроль.** `g(0) = −0.39953528` (`x4_common.py:tc_g[0]`,
   `ARTICLE_v1.md:13`), т.е. `a = f_s(0) = −0.3995 + s·h₀`. При `s = 0`
   (неподвижная точка) `a = g₀ = −0.3995 ≠ 1`. Но `H_0(G) = G(G(−0.4))/G(−0.4)
   = G(1)/1 = G(0) = −0.3995 = a` (NOT RIGOROUS, проверка по данным). Для
   возмущённой карты `H_0(f_s) = f_s(f_s(−0.4))/f_s(−0.4)`, и отношение не
   зависит от нормировки. ✓

**Вывод B*.** Согласованность нормировки подтверждена: код считает отношение
орбиты (инвариантное к нормировке), оператор `T` в сертификате A1 использует
`a = f(0)` (та же нормировка, что в алгебре), и тождество (∗) инвариантно
относительно перемасштабирования. Расхождения нет.
