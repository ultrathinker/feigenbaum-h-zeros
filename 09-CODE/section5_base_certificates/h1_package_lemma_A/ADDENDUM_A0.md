## Вопрос 1 — нелинейное неравенство шага 4

### Постановка

Шаг 4 леммы (а0) утверждает, что для `j > k ≥ m₀`:

    ‖slice_j(u) − slice_k(u)‖₁  ≤  P_tail(k)  →  0.

В линейном приближении это очевидно (Дюамелево разложение аддитивно). В нелинейном
— приращение «содержит изменения существующих вкладов», и треугольник даёт лишь
`2·P_all`, что к нулю не стремится. Значит, нужна производная оценка.

### Ключевой структурный факт: `DT(G)` сохраняет `{l = 0}`

Левый собственный функционал `l` удовлетворяет `l ∘ DT(G) = δ · l`
(`proj_codex`, `level_tail_certificate.py:19` `pperp = ‖P_perp‖₁`, где
`P_perp = I − h·l`). Для `p ∈ ker(l)` (поперечное подпространство):

    l(DT(G)[p]) = δ · l(p) = 0.

Значит **`DT(G)` переводит `{l=0}` в `{l=0}`**: поперечное подпространство
инвариантно относительно линеаризованного оператора
(`A1_ANALYTICITY_PROOF.md:64-89`, оценка композиции).

### Рекурренция в вариациях

Разложим срез: `slice_ℓ(u) = G + s_{m₀}(u)·h + p_ℓ(u)`, где `p_ℓ ∈ {l=0}`
(чисто поперечная поправка). h-компонента `s_{m₀}(u)·h` одинакова для всех `ℓ`
(усиление `δ^{ℓ−m₀}` гасится убыванием `s_ℓ = u·AU₀/δ^ℓ`, см. `IDENTITY_B.md`
§B.4). Поэтому **все приращения лежат в `{l=0}`**.

Рассмотрим переход `ℓ → ℓ+1`. Срез уровня `ℓ+1` строится из возмущения
`s_{ℓ+1} = s_ℓ/δ` (а не `s_ℓ`). Ренормализация уровня `ℓ−m₀` шагов, применённая
к `G + (s_ℓ/δ)·h`, даёт:

    T^{ℓ−m₀}(G + (s_ℓ/δ)·h) = G + (s_{m₀}/δ)·h + q_ℓ ,

где `q_ℓ ∈ {l=0}` — поперечная поправка, **квадратичная по возмущению**. Именно:
по лемме W (`level_tail_certificate.py:26-34`) `Q_j ≤ QCOEF·s_j²` равномерно,
поэтому вклад от возмущения `s_ℓ/δ` есть `QCOEF·(s_ℓ/δ)² = QCOEF·s_ℓ²/δ²`.
Отсюда:

    ‖q_ℓ‖₁ ≤ ‖p_ℓ‖₁ / δ²   (та же структура, возмущение в δ раз меньше).

Затем применяется ещё один шаг `T`:

    p_{ℓ+1} = DT(G)[q_ℓ] + R_ℓ ,

где `R_ℓ` — нелинейный остаток `(1/2)D²T(G)[ε_ℓ, ε_ℓ] + …`,
`ε_ℓ = (s_{m₀}/δ)·h + q_ℓ`, и **`DT(G)[q_ℓ] ∈ {l=0}`** по структурному факту
выше.

### Gronwall–константность

Взяв нормы (с `‖DT(G)^r P_perp‖₁ ≤ Cs·μ^r` из `proj_codex`):

    ‖p_{ℓ+1}‖₁ ≤ (Cs·μ / δ²)·‖p_ℓ‖₁ + ‖R_ℓ‖₁
                ≤ 0.0882·‖p_ℓ‖₁ + ‖R_ℓ‖₁ .

**Здесь `0.0882 < 1` — несущее число.** Оно есть `(‖DT(G) P_perp‖₁) / δ² =
(Cs·μ) / δ² = 5.496·0.35 / 21.80`. (Асимптотически ещё лучше: спектральный
радиус `μ/δ² = ratioP = 0.016`.)

Остаток `‖R_ℓ‖₁ ≤ K·‖ε_ℓ‖₁² ≤ K·(s_{m₀}² + ‖p_ℓ‖₁²)`. При
`s_{m₀} ≈ 10⁻⁴`, `‖p_ℓ‖₁ ≤ P_all ≈ 10⁻⁷`: `‖R_ℓ‖₁ ≤ K·10⁻⁸` — пренебрежимо.

Следовательно, `‖p_{ℓ+1}‖₁ ≤ 0.0882·‖p_ℓ‖₁ + K·10⁻⁸`. По принципу сжимающих
отображений `p_ℓ → p_∞`, и

    ‖p_ℓ − p_∞‖₁ ≤ 0.0882^{ℓ−m₀}·‖p_{m₀} − p_∞‖₁ .

Приращения убывают геометрически:

    ‖p_{ℓ+1} − p_ℓ‖₁ ≤ 0.0882^{ℓ−m₀}·(1 + 0.0882)·‖p_{m₀} − p_∞‖₁ + O(10⁻⁸) .

**Вывод:** `{slice_ℓ}` — последовательность Коши в `C(D̄, ℓ¹)` со скоростью
`0.0882` (норма) или `ratioP = 0.016` (спектр). Шаг 4 выведен, не заявлен. ∎

## Вопрос 2 — неустойчивая компонента и `D_EXIT`

### Что считает `D_star`

`exit_de(k)` (`level_tail_certificate.py:51-57`) распространяет возмущение
`Φ(s)` (`s = t/δ^{k+1}`) через `n = k−7` шагов ренормализации до базы. Возвращает
два скаляра:

- **`D`** — поперечная D-переменная: распространяется через `L1`/`L2` (нормы
  `‖DT‖₁`/`‖DT²‖₁`, `:47` `q = L2/δ⁴ = 0.427`).
- **`e`** — l-компонента (снос вдоль неустойчивого направления `h`):
  распространяется через `δ`/`δ²` плюс связь `lKrh·D` от D-переменной
  (`:55` `e = δ²·e + lKrh·(δ+L1)·D`).

`D_star = sup_k D_exit(k) = 5.17·10⁻⁸` (при `k = 8`,
`level_tail_certificate.json:25`); `e_star = sup_k e_exit(k) = 1.25·10⁻⁸` (при
`k = 8`, `:27`). Из `ld_audit.py:55` `compute_ld.log`: `e` — это
«`l`-component of Lemma-3 gap», т.е. снос вдоль `h`.

### Разве `e` не обнуляется за счёт постоянства `s_{m₀}·h`?

**Нет — `e` измеряет не ведущую `h`-компоненту, а её нелинейную поправку.**
Ведущая `h`-компонента среза `s_{m₀}(u)·h` действительно постоянна и сокращается
в приращении. Но нелинейные члены `D²T(G)`, `D³T(G)` генерируют **поправку к
`s_{m₀}·h`** — малый снос вдоль `h`, который и есть `e`. Эта поправка
нелинейна (порядка `s²`) и не сокращается сама собой.

### Входит ли `D_star` / `e_star` в `P_tail(k)`?

В моей формулировке леммы (а0) участвует только `P_all` (Дюамелева сумма). Но
`r_s = P_all + ‖P_perp‖₁·D_star` (`radius_K284_certificate.py:14`,
`r_s = 3.566e-7`) имеет второе слагаемое `2.808542·5.17e-8 = 1.45e-7` — это 41 %
радиуса. Его надо учесть.

**D_star (D-переменная).** DE-матрица `B = [[q,0],[c,p]]`, `q = 0.427`
(`level_tail_certificate.py:47`, `:90`) даёт: `D_exit(k+2) ≤ q·D_exit(k)`. Хвост:

    Σ_{j>k} D_exit(j) ≤ D_star · q^{(k−m₀)/2} / (1 − √q) .

Скорость убывания: **`√q = 0.654` за уровень** (`q = 0.427` за два уровня).
`0.654 < 1`. ✓

**e_star (l-компонента).** Собственное значение DE-матрицы для `e`-компоненты:
`p = 1/δ² = 0.046` (`:47`, `:90`). Хвост убывает со скоростью
**`√p = 1/δ = 0.214` за уровень**. `0.214 < 1`. ✓ Это и есть темп `δ/δ² = 1/δ`,
о котором говорит оркестратор.

**Итог по хвосту.** Полный хвост (Дюамель + DE) убывает со скоростью
**медленнейшей компоненты**:

    P_tail(k) ≤ P_all·ratioP^{k−m₀} + (‖P_perp‖₁·D_star)·(√q)^{k−m₀}
                + (‖h‖₁·e_star)·(1/δ)^{k−m₀} .

Медомленнейший темп: `max(ratioP=0.016, √q=0.654, 1/δ=0.214) = 0.654` за уровень.
Все три `< 1`. **Свойство Коши установлено.** ✓

### Проверка `tube_radius`

При `k = m₀`: `P_tail(m₀) ≤ P_all + ‖P_perp‖₁·D_star + ‖h‖₁·e_star/(1−1/δ)`:

    = 2.113e-7 + 1.453e-7 + 6.331·1.25e-8/0.786
    = 2.113e-7 + 1.453e-7 + 1.01e-7
    = 4.58e-7 < tube_radius = 5.44e-7 .  ✓

(Третье слагаемое — l-компонентный хвост; оно не входит в исходный `r_s`, но
вписывается в трубку: реальный запас до `tube_radius` — `0.87·10⁻⁷`, а не
`headroom = 1.874e-7` к неполному `r_s`.)

### Уточнение третьего слагаемого (BRIEF_R, R1)

Третье слагаемое `‖h‖₁·e_star/(1−1/δ)` зависит от выбора `e_star`. В архиве
их **два** (та же пара вычислений, что и для `D_star`):

- **tight**, `e_star = 1.2453·10⁻⁸` (`level_tail_certificate.json:27`, M3=1834,
  сертифицированный прямой сертификат) — **применимое** значение (то же M3=1834,
  что и для `D_star` в `r_s` и для `P_all`).
- **conservative**, `e_star = 1.5053·10⁻⁸` (`compute_ld.json:3`, M3=123479,
  грубая Коши-оценка) — запасная верхняя граница.

Пересчёт (Arb 512, `δ = 4.669201609102990671853`,
`1−1/δ = 0.7858306`, `‖h‖₁ = 6.331193600692640`):

    tight:        6.3311936 · 1.24528·10⁻⁸ / 0.7858306 = 1.003·10⁻⁷
    conservative: 6.3311936 · 1.50534·10⁻⁸ / 0.7858306 = 1.213·10⁻⁷

Отсюда `P_tail(m₀)`:

    tight (M3=1834, применимо):   2.113e-7 + 1.453e-7 + 1.003e-7 = 4.569e-7
    conservative (M3=123479):     2.113e-7 + 1.453e-7 + 1.213e-7 = 4.779e-7

Оба `< tube_radius = 5.44e-7`. Выше использовано применимое (tight) значение
`(1.245·10⁻⁸ → 1.003·10⁻⁷, округлено до 1.01·10⁻⁷)`. Оркестратор в `BRIEF_R`
приводил `1.2128·10⁻⁷` — это **консервативная** оценка (M3=123479), верная как
верхняя граница, но не применимая/рабочая: выбор `e_star` должен совпадать с
M3=1834, использованным всюду в пакете (`D_star`, `P_all`). Итог: прав
`ADDENDUM_A0` по применимой величине (`4.57·10⁻⁷`); число оркестратора
`4.78·10⁻⁷` — корректный консервативный потолок. Полный разбор —
`cert_D/RECONCILE_R.md` (R1).
