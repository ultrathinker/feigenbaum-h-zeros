## 1. Что считает каждый скрипт и в чём формулы совпадают

Оба скрипта оценивают **одну и ту же величину**: верхнюю грань нормы
проекции зазора уровней `||P w_exit||_1` (l1-норма устойчивой части на
выходе телескопа, `P = P_perp`), которая входит в радиус трубки
`radius_K284_certificate.json` как `P_exit_ceiling`.

| | `duhamel_audit.py` → `duhamel_ds.json` | `level_tail_certificate.py` → `level_tail_certificate.json` |
|---|---|---|
| цель | `3e-7` | `3e-7` |
| M3 | `123479` (Коши, `K/(r0-r1)`), строка 56 | `1834` (прямой сертификат), строка 13 |
| Q-член | рекурсивный `refined_Q_bound`: `s²·nv0 + s·K·nh·w + (K/2)w² + (M3/6)a³` | закрытая формула `QCOEF = q2 + K·nh·C1·s8 + K·C1²·s8²/2 + M3·(nh+C1·s8)³·s8/6` |
| ядро (устойчивая часть) | `Cs_res·mu^j` (j = 0..n-1) | `pperp + Cs·ratioP/(1-ratioP)`, `ratioP = mu/delta²` |
| результат | `P_star_refined = 6.686e-7`, `pass: false` | `P_all_levels_upper = 2.113e-7`, `pass: true` |

**Совпадение формул.** Обе ветви используют:
- квадратичный член `q2 = nv0 = 111.55` как `||D²T(G)[h,h]||/2` (одна и та же константа: `nv0 = 111.550905121` в duhamel, `q2 = 111.550905120798913` в level_tail);
- кубический член через `(M3/6)·(bound)^3`;
- устойчивое ядро через `Cs·mu^j` / `Cs·ratioP/(1-ratioP)` — `ratioP = mu/delta²` — это **точная сумма геометрической прогрессии** ядер `Cs·mu^j` (с добавкой `pperp = 2.808542` в level_tail, отсутствующей в duhamel как отдельный член, но дублированной там ядром `j=0` при `tight_j0`).

Разница в **двух** местах, и обе они — в пользу level_tail:
1. **M3**: `123479` (Коши-потолок) против `1834` (прямой сертификат) — в 67 раз;
2. **структура Q**: duhamel суммирует пошаговую рекурсивную цепочку
   (`w_j` растёт за счёт `K·a_j²/2` на каждом шаге), level_tail использует
   закрытую форму с парным инвариантом `w ≤ C1·s²` (`C1 = 1280`) — она
   алгебраически мажорирует ту же цепочку (Лемма W / w_pair_invariant) и
   даёт более тугое, но **строгое** сверху значение.

## 2. Откуда `M3 = 123479`

`duhamel_audit.py:56`:

    M3 = A("123479")    # >= K/(r0-r1) = 123478.2608...

Грубая оценка по Коши: `K = 284` (глобальный сертификат `k_global_certificate.json`),
`r0 = 2.5e-3`, `r1 = 2.0e-4`, поэтому `K/(r0−r1) = 284/0.0023 = 123478.26`, округлено
вверх до `123479`. Это легитимная верхняя граница `||D³T||` через Коши, **но она в
67.3 раза больше** прямого сертификата (см. п. 3). Именно она, будучи подставлена
в кубический член `(M3/6)·a³`, раздувает `P_star_refined` до `6.686e-7 > 3e-7`.

## 3. Откуда `M3 = 1834`

Прямой сертификат `m3_global_certificate.json`:

    "M3_global_upper": 1833.667,      (в интервальной записи +/- 1.67e-150)
    "M3_chosen": "1834",
    "radius": "2e-4",
    "complete_output_degree": 19602,
    "pass": true

То есть прямым коэффициентным подсчётом (полный выход степени 19602, хвосты
мод >= 100 включены, комплексные боксы 512 бит) доказано, что
`sup_{B(G, 2e-4)} ||D³T|| ≤ 1833.667`, и выбран `M3_chosen = 1834`.
Это **в 67 раз туже** Коши-оценки: `123479 / 1834 = 67.3`.

Ключевой смысл: `K/(r0-r1)` оценивает третью производную через `K` на всём
кольце ширины `r0-r1 = 2.3e-3`, а прямой сертификат — через фактическую
биллинейную/трилинейную структуру оператора на радиусе `2e-4`, где оператор
уже хорошо сходится. Обе границы сверху, но `1834` — содержательная, `123479` —
крайне грубая.

## 4. ПРИМЕНИМОСТЬ — главный пункт

**Вопрос брифа:** действует ли сертификат M3 (радиус `2e-4`) на фактический
заход орбиты `Amax = 1.3479e-4` из `duhamel_ds.json`, и измеряет ли `Amax`
ту же норму и то же отклонение?

**Ответ: ДА, применим. Это одна и та же норма и один и тот же объект.**

1. **Норма.** `Amax` в `duhamel_audit.py` есть максимум по всем шагам `j`
   величины `a_j = s_j·||h|| + w_j`, где `s_j·h` — затравочная компонента,
   `w_j` — накопленное отклонение, обе в **l1-норме Тейлоровских коэффициентов**
   (`nh = ||h||_1 = 6.331`). Сертификат M3 живёт в той же l1-алгебре
   (комплексная l1-банаховская алгебра коэффициентов, `a1_certificate.json`,
   `k_global_certificate.json`). Нормы совпадают.

2. **Объект.** M3 сертифицирует `sup ||D³T(x)||` для `x` из шара `B(G, r1)`
   с `r1 = 2e-4`, где `G` — неподвижная точка. Фактические точки телескопа
   `x_j = T^j(S_k)` лежат в том же шаре вокруг **той же** `G`: Лемма 2
   (`w36_close_v2.md`) даёт `||x_j − G|| ≤ 6.34e-4`, а более точно —
   `a_j ≤ Amax = 1.348e-4`. Отклонение измеряется от той же точки `G` в той
   же норме.

3. **Сопоставимость величин.** `Amax = 1.3479e-4 < r1 = 2e-4` — сертификат
   радиуса `2e-4` покрывает заход с запасом `2e-4/1.348e-4 = 1.48x`. Для
   сравнения, затравочный член level_tail использует ту же величину:
   `|s8|·(nh + C1·s8) = 1.3485e-4`, то есть **одна и та же точка**
   (`s8 = t/delta^8`, `t = 4.7911`). Совпадение `Amax ≈ |s8|·(nh+C1·s8)`
   с точностью до 1e-7 подтверждает, что оба скрипта измеряют один и тот же
   объект.

4. **Единственная оговорка:** сертификат M3 действует на шаре
   `B(G, r1)` радиуса `r1 = 2e-4` и, следовательно, мажорирует `||D³T(x)||`
   только для `x` внутри этого шара. Заход орбиты внутри шара — да.
   Внешний кусок (`F = T^7`) к M3 отношения не имеет — он покрыт отдельной
   трубкой `radius_K284_certificate.json` (`r_s ≤ 5.44e-7`). Нарушений
   применимости не обнаружено.

**Вывод:** `Amax` и радиус M3 измеряют **одну и ту же** l1-норму отклонения от
`G`; `Amax` строго меньше радиуса сертификата. Никакой подмены норм или
объектов нет — статус пакета от этой ветки не меняется.

## 5. Вердикт

1. `duhamel_ds.json` с `M3 = 123479` и `pass: false` — **устарел**: он
   использовал Коши-оценку, которая была заменена прямым сертификатом
   `M3 = 1834` ещё до заморозки пакета. Той же величины, что `P_all_levels_upper`.
2. **Актуальная величина** — `level_tail_certificate.json::duhamel_all_levels`,
   `P_all_levels_upper = 2.1134e-7 ≤ 3e-7`, `pass: true`. Она же используется
   в `radius_K284_certificate.json` (`P_exit_ceiling = 2.113426e-7`).
3. **Просто «устарел» недостаточно честно**: в архиве не должно оставаться
   файла с `pass: false` для той же величины без пояснения. Поэтому (п. 6)
   `duhamel_ds.json` **пересчитан с правильным M3 = 1834** и перезаписан с
   `pass: true`, а его «дедушка»-версия с M3=123479 сохранена как
   `duhamel_ds_M3_123479_backup.json` для истории.

**Критический нюанс, вскрытый при пересчёте:** простая замена M3 в самой
рекурсии `duhamel_audit.py` (пошаговая цепочка `refined_Q_bound`) даёт
`P ≤ 3.948e-7` — **всё ещё больше `3e-7`**! Причина — пошаговая рекурсия
духеля не использует парный инвариант `w ≤ C1·s²`, её `w_j` раздувается на
`K·a_j²/2` на каждом шаге, и даже с правильным M3 сумма остаётся над порогом.
Закрытая формула level_tail (с `w ≤ C1·s²`, `C1 = 1280`) даёт `2.113e-7` и
проходит. **Это подтверждает, что проходной величиной является именно
закрытая формула level_tail, а не буквальная пошаговая рекурсия duhamel.**
Числа в п. 6 воспроизводят обе оценки.

## 6. Пересчёт (дешёвый) и приложенный результат

Пересчитано независимо (mpmath, 120 знаков; интервальные границы не нужны —
все входы — уже верхние оценки сверху, сравнение идёт на уровне «меньше ли
3e-7»):

    P_star (духель, рекурсия, M3=123479)  = 6.686142e-7   (совпадает с duhamel_ds.json: 6.686142e-7)
    P_star (духель, рекурсия, M3=1834)    = 3.947954e-7   (НЕ проходит 3e-7 — рекурсия, не закрытая формула)
    P_ALL  (level_tail, закрытая формула, M3=1834) = 2.113425e-7   (ПРОХОДИТ, совпадает с level_tail_certificate.json)

Вывод пересчёта:
- **Негативный контроль**: M3=123479 даёт 6.686e-7 > 3e-7 — именно поэтому
  старый файл был `pass: false`.
- **Закрытая формула с M3=1834** даёт 2.1134e-7 < 3e-7 — пакетная величина
  проходит с запасом 1.42x.
- **Рекурсия с M3=1834** не проходит (3.948e-7) — это диагностический факт,
  который делает выбор закрытой формулы level_tail обязательным, а не просто
  удобным.

пересчёта (обе ветки, обе оценки M3, копия формулы из спецификации).
`duhamel_ds.json` в `w36/audit_codex/` **не тронут** (архив READ-ONLY);
